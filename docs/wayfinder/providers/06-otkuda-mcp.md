## Question

У каждого поставщика свой адрес MCP на моторе (см. «Один мотор или по сервису на поставщика»), кода на маке нет (см. «Если gang.su лежит»). Как конкретный проект говорит «мне нужны Mattermost и Confluence»: строки в `.mcp.json` проекта, плагин на каждого поставщика, своя команда-подключалка — и что из этого общее на весь мак (адрес мотора, токен)? То же для сервисов на сервере, которые запускают `claude -p`.

## Решение

Выбора по проектам нет: всем потребителям — все поставщики. Что можно писать, решают права из «Токены и права».

- **На маке**
  - все поставщики подключены сразу во всех проектах;
  - подключает один плагин «мотор» со всеми адресами (`…/mattermost`, `…/confluence`, …), он лежит в репо мотора;
  - новый поставщик — строка в плагине, на мак приезжает с обновлением плагина, руками ничего не прописываем;
  - токен Claude на маке — в переменной окружения (например, `MOTOR_TOKEN` в `~/.zshrc`), плагин подставляет его в `Authorization: Bearer`.
  - Проверить при сборке: исследование не подтвердило, что Claude Code передаёт переменную в заголовок удалённого сервера. Если не передаёт — токен в `userConfig` плагина.
- **Сервисы на сервере** (recaps, go, …)
  - у всех один общий файл подключения со всеми поставщиками: `claude -p --strict-mcp-config --mcp-config <файл>`;
  - токен у каждого сервиса свой, в его окружении.
- **Отдельные адреса у поставщиков остаются** — чтобы в `/mcp` можно было выключить одного.
