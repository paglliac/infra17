# Мотор поставщиков

Одна программа на `gang.su`, через которую все — Claude на маке и сервисы на сервере — ходят к внешним системам (Mattermost, календарь, Confluence, …) и к данным хаба. Вместо восьми копий клиента Mattermost и токенов в десяти местах — один код и одно место для токенов.

```
 Claude на маке ──┐                       ┌── Mattermost, календарь, ktalk, Todoist, оргструктура
 recaps ──────────┼──▶  motor.gang.su  ───┼── Confluence, Jira (через VPN Авито)
 хаб SecondBrain ─┘                       └── хаб: tracker, people, inbox, triage
```

Хаб одновременно потребитель (берёт через мотор Mattermost, календарь, …) и поставщик (мотор отдаёт его tracker, people, inbox, triage).

## Поставщики

| поставщик | что внутри | писать | как мотор туда ходит |
|---|---|---|---|
| `mattermost` | сообщения, каналы, сохранённые, люди | никому (ни отправка, ни снятие «сохранено») | напрямую |
| `calendar` | Exchange-календарь | нечего | мимо NL-туннеля (`direct`) |
| `ktalk` | встречи и расшифровки | нечего | мимо NL-туннеля (`direct`) |
| `org` | оргструктура `org.avito.ru` | нечего | проверить при заведении (может, через VPN) |
| `todoist` | задачи | всем | напрямую |
| `confluence` | `cf.avito.ru`: страницы, поиск | никому (комментарии тоже нет) | через VPN Авито |
| `jira` | поиск по JQL, задача, связанные, спринты | никому | через VPN Авито, `tracker-proxy` + личный сертификат |
| `tracker`, `people`, `inbox`, `triage` | данные хаба | всем | HTTP хаба (`gang.su/api/...`) |

Права одни на поставщика для всех потребителей, не своё у каждого.

Не в моторе: unit и perf_review (остаются на маке со своими локальными MCP), budget и ZenMoney (отдельная полоса), корпоративный `avito mcp` у скилла `maturity-rollup`.

## Как устроен

- **Тупой прокси.** Своей копии данных, расписания и базы у мотора нет — только токены. Опрос по расписанию и «уже разобрал» — у каждого потребителя свои.
- **Входы.** Каждое действие — один адрес: `GET motor.gang.su/<поставщик>/<действие>` → JSON, например `…/mattermost/saved_posts`.
  - MCP мотор собирает сам поверх тех же адресов: действие описывается один раз, имя инструмента = конец адреса (`saved_posts`).
  - У каждого поставщика свой адрес MCP (`…/mattermost`, `…/confluence`, …) — чтобы в `/mcp` можно было выключить одного.
- **Длинные списки** — лимит по умолчанию (сообщения 30, сохранённые 100, каналы 100, люди 20, встречи 30) плюс фильтры поставщика («с даты», «за N дней»). Листания «дальше» и пометки «есть ещё» нет. Одиночные большие вещи (расшифровка ktalk) — целиком. Ответ MCP — до 25k токенов.
- **Ошибки** — код и человеческий текст «что делать»:
  - 503 — поставщик лежит («VPN Авито отвалился — введи код на motor.gang.su»);
  - 401 — протух внешний токен («токен ktalk протух — вставь новый на motor.gang.su»);
  - 403 — запись запрещена.
  - В MCP — ошибка инструмента с тем же текстом. Сам мотор никому не пишет: о поломке узнаёшь, когда споткнулся запрос, или на страничке. Фоновые потребители (инбокс хаба, recaps) показывают ошибку мотора у себя, а не глотают.
- **Токены.**
  - Внешние (Mattermost, ktalk, Exchange, Confluence, Todoist, org, сертификат Jira) — только в моторе, вводятся на страничке.
  - Вход в мотор — у каждого потребителя свой токен (`Authorization: Bearer`). Протёк один — отзываешь только его.
- **Страничка `motor.gang.su`.**
  - Свой пароль (хэш и сессия, как у хаба; с хабом вход не общий).
  - Поставщики: поле для токена и состояние «работает / протух», когда последний раз ответил.
  - Потребители: «новый» (имя → токен, показывается один раз), список с «последний раз ходил» и кнопкой «отозвать». Журнала вызовов нет.
  - VPN Авито: состояние «работает / лёг» и поле для TOTP-кода.
- **VPN Авито на `gang.su`.** OpenVPN: сертификат + логин + TOTP. Код вводится руками на страничке раз в ~3,3 дня и после каждой перезагрузки сервера; секрета TOTP на сервере нет. Пока VPN лёг — `jira` и `confluence` отвечают 503, остальные работают. Напоминаний нет.
- **Если `gang.su` лежит** — Claude на маке без данных поставщиков. Офлайн-режима и кода на маке нет.

## Где живёт и как деплоится

- **Репо** — своё (`paglliac/motor`): код мотора и плагин «мотор» для мака.
- **Деплой** — запись `motor` в `group_vars/all/services.yml` этого репо: свой порт, поддомен `motor`, `.env`, `health`, `make deploy S=motor`. Своего `deploy/` у мотора нет.
- **`direct` мотора** — хосты, которые не пускают NL-адрес: `exchange.avito.ru`, `avito.ktalk.ru` (переезжают сюда из `direct_taken` у SecondBrain, когда хаб перестаёт ходить к ним сам).
- **Общий файл подключения для `claude -p`** — один на сервер, кладёт этот репо (например `/etc/motor/mcp.json`): адреса всех поставщиков, токен — `${MOTOR_TOKEN}` из окружения сервиса.

## Как добавить поставщика

1. В коде мотора: действия поставщика по общим правилам (адрес → JSON, лимиты, фильтры, ошибки с текстом).
2. Правило записи: читать всем; писать — всем или никому.
3. Если нужен внешний токен — поле на страничке и проверка «работает / протух».
4. Если хост не пускает NL-адрес — в `direct` мотора; если внутренний адрес Авито — через VPN (503 при отвале).
5. Строка с адресом MCP в плагине и в общем `--mcp-config`.
6. `make deploy S=motor`, обновить плагин на маке. Проверка: действие отвечает по `curl` с токеном и видно в `/mcp`.

## Как подключить потребителя

Выбора поставщиков нет: всем — все.

- **Claude на маке** (любой проект)
  1. На страничке — новый потребитель «мак», токен в `MOTOR_TOKEN` в `~/.zshrc`.
  2. Поставить плагин «мотор» из репо мотора — он подключает все адреса и подставляет токен в заголовок.
  - Если Claude Code не подставляет переменную в заголовок удалённого сервера — токен в `userConfig` плагина (проверяется в задаче К2).
- **Сервис на сервере, который запускает `claude -p`**
  1. На страничке — новый потребитель с именем сервиса.
  2. `make env S=<сервис> K=MOTOR_TOKEN`.
  3. Запуск: `claude -p --strict-mcp-config --mcp-config /etc/motor/mcp.json`.
- **Программа, которая ходит сама** (инбокс хаба, recaps)
  1. Токен — как выше.
  2. `GET motor.gang.su/<поставщик>/<действие>` с `Authorization: Bearer $MOTOR_TOKEN`; ошибки мотора показывать у себя.

## Задачи

### Как работать

- Задача **свободна**, если в «взял» пусто и всё из «после» в статусе «готово».
- **Взять** — вписать себя в «взял», закоммитить и запушить в `main` до начала работы. Параллельная сессия сначала делает `git pull` и видит, что задача занята.
- **Закончить** — статус «готово ДД.ММ», и если всплыло что-то, что касается других задач, — одна строка в «Всплыло» под таблицей.
- Фаза 1 — группы по приоритету (сначала Mattermost и календарь, хаб последним), внутри группы параллельно. Жёстко держит только «после».
- Фаза 2 — порядка нет: каждое переключение независимо, бери в любом порядке, когда удобно.
- Переключение потребителя на мотор и уборка его старого — одна задача: переключил → сразу удалил старое.

- **К1. Каркас мотора.** Репо `paglliac/motor`; запись в `services.yml`, `motor.gang.su` с HTTPS; страничка с паролем и потребителями; общий механизм «действие → адрес → MCP», ошибки, лимиты. Готово: страничка открывается, выписанный токен проходит, без токена — 401.
- **К2. Плагин и `--mcp-config`.** Плагин в репо мотора со всеми адресами; `/etc/motor/mcp.json` раскладывает этот репо. Сначала проверить, подставляет ли Claude Code `${MOTOR_TOKEN}` в заголовок — на маке и в `--mcp-config`; если нет — `userConfig` плагина. Готово: на маке и в тестовом `claude -p` на сервере виден хотя бы один поставщик.
- **П1. Mattermost.** Действия как в нынешнем `mattermost_global` (10 инструментов), только чтение. Токен — на страничке. Готово: `…/mattermost/saved_posts` отвечает; запись — 403.
- **П2. Календарь.** Перенести код Exchange из хаба; `exchange.avito.ru` в `direct` мотора (в `direct_taken` у SecondBrain пока остаётся). Готово: встречи на сегодня читаются живьём.
- **П3. VPN Авито на `gang.su`.** OpenVPN с сертификатом и логином, TOTP — поле на страничке, состояние «работает / лёг». Готово: после ввода кода с сервера отвечают `cf.avito.ru` и `prod.k.avito.ru`; при отвале `jira`/`confluence` — 503 с текстом «введи код».
- **П4. Confluence.** `cf.avito.ru`, только чтение (без комментариев). Личный atlassian.net не заводим. Готово: поиск и страница читаются.
- **П5. Jira.** `tracker-proxy` (`https://prod.k.avito.ru/service-tracker-proxy`, `POST /<метод>/`, ответ — `jsonBody` в base64; пример — класс `Tracker` в `~/avitoid_opreview/opreview/collect_sql.py`). Личный сертификат `~/.avito/certs/personal.{crt,key}` (до 02.01.2027) — на страничке, с «работает / протух». Лимит 10 запросов / 10 с, общий с opreview. Готово: JQL-поиск и задача читаются.
- **П6. ktalk.** Перенести код из хаба; токен — на страничке (вставка из «Copy as cURL»); `avito.ktalk.ru` в `direct` мотора. Готово: список встреч и расшифровка целиком.
- **П7. Оргструктура.** Перенести из хаба; сначала проверить, отвечает ли `org.avito.ru` с `gang.su` без VPN. Готово: поиск человека и его команда.
- **П8. Todoist.** Чтение и запись (удаление задачи). Готово: список и удаление тестовой задачи.
- **П9. Хаб как поставщик.** `tracker`, `people`, `inbox`, `triage` — мотор ходит в HTTP хаба своим токеном. Набор действий — по оригиналам `SecondBrain-new/server/mcp`, а не по разошедшимся `~/mcp/secondbrain/*` (там нет `run_capture` и agenda, а 4 инструмента triage для групп зовут несуществующие адреса). Готово: задачи tracker читаются и создаются через мотор.

- **Х5. Мак: старые ключи.** Пройти устаревшие копии токенов (минимум 5 мест, два в Obsidian Vault с правами 0644) и удалить то, что больше никем не читается. `~/mcp/mattermost/.env` оставить.

Сначала проверить ретранслятор Mattermost → FCM в mm-recaps: если ему нужно что-то, чего нет в «тупом прокси» (websocket, подписка), — вынести на решение до переключения. Готово: дайджест собирается через мотор, `mm.py` удалён.
- **Х7–Х11. Хаб.** Каждый поставщик — отдельно. Первая взятая задача заодно заводит потребителя «хаб» и кладёт его `MOTOR_TOKEN` в окружение хаба (деплой хаба — свой, в `tasks17`). В каждой: хаб ходит через мотор, свой код поставщика и его токен из `credentials` в `tracker.db` удаляются, ошибки мотора видны в инбоксе.

  - **Х8. Календарь** — копия для дашборда раз в 5 мин остаётся в хабе, заполняется через мотор; `exchange.avito.ru` убрать из `direct_taken` у SecondBrain.
  - **Х9. ktalk** — инбокс берёт встречи через мотор; `avito.ktalk.ru` убрать из `direct_taken`.
  - **Х10. Todoist** — инбокс читает и удаляет задачи через мотор.
  - **Х11. Оргструктура** — people в хабе остаётся своим списком алиасов и заметок поверх оргструктуры из мотора.
